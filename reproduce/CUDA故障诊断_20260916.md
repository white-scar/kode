# 服务器 CUDA 故障诊断（2026-09-16）

## 结论：硬件级掉卡 -> 驱动级故障 -> 全机器 GPU 不可用（需 root）

### 1. 直接原因
- 2026-09-16 06:52:33 UTC（北京时间 14:52）：
  `NVRM: Xid (PCI:0000:63:00): 79, GPU has fallen off the bus.`
  掉线卡 UUID：`GPU-9af977a3-3d50-75f0-1cd5-fa377beab51e`（设备节点 /dev/nvidia3）
- 紧接着：
  `NVRM: Xid (PCI:0000:63:00): 154, GPU recovery action changed from 0x0 (None) to 0x2 (Node Reboot Required)`
  -> 驱动自己判定：需要重启节点。

### 2. 该卡现状（已物理掉线，非软件问题）
- `lspci -s 63:00.0` -> `Device 2685 (rev ff)`，`!!! Unknown header type 7f`
  rev ff = 读到全 0xFFFFFFFF，卡已不响应 PCIe 配置空间。
- `/proc/driver/nvidia/gpus/.../information` 里该卡 `Bus Type: PCI`（其它 7 张都是 PCIe）。
- `nvidia-smi -L` 里没有它的 UUID；其余 7 张（17:00.0 / 2a:00.0 / 3d:00.0 / 99:00.0 / ab:00.0 / bd:00.0 / e1:00.0）均为 `rev a1` 健康、0 MiB、0%。

### 3. 为什么 7 张好卡也全废（关键）
07:28:52 UTC 之后驱动状态被污染：
```
nvAssertOkFailedNoLog: ... Call timed out [NV_ERR_TIMEOUT] ... kernel_gsp_falcon_ga102.c:218
s_executeBooterUcode_TU102: failed to execute Booter: status 0x65
iovaspaceDestruct_IMPL: 3 left-over mappings in IOVAS 0x6300
```
实测（libcuda.so.1 直调）：
- `cuInit(0) -> 999` (CUDA_ERROR_UNKNOWN)
- `cuDeviceGetCount -> 3` (CUDA_ERROR_NOT_INITIALIZED)
- torch: `cuda.is_available()=False`；`CUDA_VISIBLE_DEVICES=0/1/2/3/4/5/6` 单卡全部 `CUDA unknown error`；`=7` -> count=0
=> 这是**驱动全局**故障，机器上任何用户现在都跑不了 GPU，不只是我们。
`nvidia-smi` 仍是"假绿灯"（它走 RM-only 路径，不经 UVM）。

### 4. 我们做不了什么
- `sudo` 需要密码（无 passwordless sudo）
- `echo 1 > /sys/bus/pci/devices/0000:63:00.0/remove` -> Permission denied
- `nvidia-smi --gpu-reset` -> Insufficient Permissions

### 5. 交给管理员的修复指令（任选）
```bash
# A. 首选：重启（Xid 154 已明确 Node Reboot Required；本机已 244 天未重启）
sudo reboot

# B. 不能重启时，尝试软件恢复：
sudo rmmod nvidia_uvm nvidia_drm nvidia_modeset nvidia
sudo modprobe nvidia_uvm
# 再把掉线卡从 PCI 摘除后重扫（有可能拉不回来，那就是供电/插槽/硬件问题）
echo 1 | sudo tee /sys/bus/pci/devices/0000:63:00.0/remove
echo 1 | sudo tee /sys/bus/pci/rescan
```
预期：重启后 7 张健康卡恢复可用（掉线卡可能永久失效，属硬件）。
